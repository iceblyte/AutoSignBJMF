「静默工具」— 中性画布 · 描边分层 · 一个强调色

给一个每天只被想起一次、却要 7×24 常驻的工具做界面。判断标准不是首屏好看，而是第 200 次打开时是否依然一眼看清 「今天签到了没有、下次几点、哪里出错了」。所以：不堆装饰，层级交给排版；阴影只给浮层；状态色只表达状态。

原型拆成三份，互不混排：10-exe（Rust 桌面端，6 屏 + 托盘）、 20-web-user（3 屏，组件契约）、 30-web-admin（3 屏，含批量）。 三份共用本页的令牌与组件，差异只在密度与容器。

01参考与取舍

三家参考各取一段，不整包照搬。共同点是：界面自身要「消失」，把注意力留给状态和数据。

ElegantClipboard（GPUI 2.0）
  • 取可配圆角 + 明暗双主题 + 跟随系统强调色，本地优先的「安静桌面工具」气质。
  • 取托盘常驻、不抢焦点的窗口行为，映射到我们的「关窗到托盘」。
  • 弃Mica / 毛玻璃材质 —— WebView 与 tkinter 都还原不了，只做视觉上限承诺不了落地。
dbx（Tauri + shadcn-vue）
  • 取紧凑桌面密度：工具条 32px 高、侧栏 240px、状态 pill、表格悬浮才出操作。
  • 取侧栏 + 工具条 + 主区 + 详情抽屉的四段结构，管理端直接沿用。
  • 弃多标签、命令面板、代码编辑器等重型范式 —— 我们的任务只有「配一次、看结果」。
Apple / SF 体系
  • 取字号层级与留白节奏：19 / 13.5 / 12 / 11.5 四档，靠字重与灰度拉层级。
  • 取单一强调色，语义色只在需要判断的地方出现。
  • 弃营销页式大标题、巨幅留白 —— 这是工具，一屏要装下地点、时间、日志。
2026 数据型界面共识
  • 取描边优先于阴影：1px hairline 分层，阴影只留给菜单/弹窗/Toast。
  • 取先设计空状态与骨架屏，再设计有数据的样子 —— 新用户第一眼看到的就是空。
  • 取150–200ms 的确认型动效：只解释「刚刚发生了什么」，不做入场表演。
DESIGN DIRECTION
静默工具（Calm Tool）

中性灰画布 + 纯白卡片 + 1px 描边 + 10~12px 圆角 + 唯一蓝色强调色。三端（Web 用户端 / 管理端 / exe） 共用同一套令牌，只在密度上分叉：Web 行高 44、exe 36、管理端表格 42。

WHY NOT 现在的样子
不是不好看，是「不像同一套」

现状：用户端是表单墙、管理端是表格 + 右栏、exe 是 tkinter 的表格堆叠，三端各说各话；状态只有颜色没有文案； 空状态与错误态基本没设计。v2 的目标是同一套语法 + 三种密度，而不是三份皮肤。

06状态语义

现在只有「绿/灰两态」。v2 定四个状态，每个状态都有颜色、圆点、文案，三端措辞必须完全一致。

状态形态色值出现位置与文案
运行中实心点 + 文案#0D9488exe 状态栏 / 账号行；表示调度器在线且该账号启用中。侧栏极窄时退化为纯圆点。
需重新登录实心点 + 文案#B45309Cookie 失效。主操作由「立即签到」变为「重新扫码」，行内给出一次性说明。
签到失败实心点 + 文案#B42318签到接口返回错误或网络异常且重试耗尽。必须同时给「查看日志」入口。
已暂停实心点 + 文案#868D97用户手动停用。灰不是错误，不出现红黄色。
禁止：只给一个圆点、没有任何语义的空胶囊；用红色表达「暂停」；用绿色表达「已启用但今天没签上」。

07品牌标识

沿用现有 logo.png（512 / 256 透明底），不重绘、不改色、不加圆角与投影。

  • 取透明底直接贴合，浅色深色都不垫白板。
  • 取图标与 logo 同源：exe / 托盘 / 任务栏用同一张 PNG 生成 ico。
  • 弃拉伸变形、描边、外发光、在深色底上再垫白底。

接口对齐清单（做 UI 之前要先补的后端）
1. 立即签到
POST /api/tasks/{id}/run
用户端 POST /api/tasks 只创建任务，没有「跑一次」。不补这个接口，用户端的「立即签到」就是假按钮。
2. 启用 / 暂停
PATCH /api/tasks/{id} → enabled
目前只有管理端 PATCH，用户端没有自己的编辑入口。
3. 重试策略入库
retry_count / retry_interval
已定为用户可编辑，所以必须入库（默认 3 次 / 5 分钟）。三端共用同一校验：次数 1–10、间隔 1–60 分钟。

10动效与可访问性

动效
  • 取140ms / ease-out：hover、按钮按下、开关滑动。
  • 取180ms / ease：步骤切换、抽屉滑入、弹窗淡入 + 上移 4px。
  • 取进度条与倒计时用 1s 线性，因为它在表达真实时间。
  • 弃首屏入场动画、卡片依次浮起、数字滚动 —— 每天开一次的工具，第三次就烦。
可访问性底线（WCAG 2.2 AA）
  • •正文对比度 ≥ 4.5:1（#545A63 on #FFF = 7.4:1）；辅助文字 ≥ 3:1。
  • •焦点环统一 3px 半透明蓝，键盘 Tab 顺序 = 视觉顺序。
  • •状态不只靠颜色：色 + 圆点 + 文案三重编码。
  • •所有图标按钮有 aria-label；Cookie / Key 默认掩码，可点击显示。

11决策记录

以下已定稿，后续实现按这张表验收；改任何一条都要同步改三端与本文档。

决策结论影响 / 落实点
桌面端技术路线 Rust + Tauri 重写，不再为 tkinter 做降级 窗口可 1:1 还原圆角、投影、36px 自绘标题栏；tkinter 版作为过渡保留
标题栏 自绘，36px，参考 dbx 窗口按钮 46×36 贴右，关闭悬停 #C42B1C；可拖拽、双击最大化
关窗行为 默认最小化到托盘，首次关闭给一次性说明 设置页可改「直接退出」；真正退出走托盘菜单
坐标拾取 定位图标 + 「拾取」，三端同一个 SVG 沿用旧原型里的 pin 图标；管理端抽屉也要有
失败重试 用户可设置：1–10 次 / 1–60 分钟，默认 3 次 / 5 分钟 数字输入，放在「每天执行时间」卡内；需入库 retry_count / retry_interval
管理端范围 到此为止：列表 + 详情抽屉 + 批量启停 / 批量改时间 不做按班级分组、7 天成功率、操作审计
移动端 不做。没有 APK、没有 IPA、也没有小程序 Web 只在 <680px 时做基础单列堆叠（避免打开就错位），不作为设计目标、不出移动端画板
Web 两端范围 契约级 3 屏：只锁字段、控件与文案，不铺状态页 等 Rust 桌面端定稿后再回头补 Web 的完整状态
下一步：设计侧到此收口，剩下的状态（离线、加载、校验失败、Cookie 过期、删除确认）在实现时按本文档的 状态语义与组件直接落地，不再单独出图。 先改 web_signin（tokens → 用户端 → 管理端），再按同一套令牌起 Rust 版界面。
